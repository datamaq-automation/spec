# Directivas de Desarrollo con Aider (Backend — FastAPI + Clean Architecture)

Este proyecto se rige por **Spec-Driven Development (SDD)**, **Clean Architecture**, **Screaming DDD** y el **Guantelete de Restricciones (*Constraint Gauntlet*)**.

---

## 1. Fuente Única de la Verdad (SSOT)
* **Especificación del Sistema:** Toda regla de negocio, contrato de API, modelo de datos y requisito funcional (FR) o no funcional (NFR) está definido en [`docs/srs-spec-backend-fastapi.md`](file:///home/agustin/proyectos_software/spec/docs/srs-spec-backend-fastapi.md).
* **Directiva:** No inventes endpoints, entidades ni schemas fuera de lo especificado en el documento SSOT. Si una instrucción del usuario modifica el diseño del sistema, consúltalo antes de proceder.

---

## 2. Las 7 Reglas Innegociables de Arquitectura
1. **Regla de Dependencia de Capas (Validada por AST):**
   * `src/domain/`: Reglas de negocio puras (DDD). Prohibido importar de `application`, `adapters`, `infrastructure`, `fastapi` o librerías de persistencia/ORM.
   * `src/application/`: Casos de uso (Interactors), DTOs y Mappers. Solo puede importar de `domain` y `pydantic`.
   * `src/adapters/`: Controladores, Presentadores y Gateways. Puede importar de `application` y `domain`. Prohibido importar de `infrastructure` o frameworks web.
   * `src/infrastructure/`: Frameworks, drivers concretos (FastAPI, SQLAlchemy, Broker) y `settings`.
2. **Archivos `__init__.py` de 0 Bytes Obligatorios:**
   * Todo `__init__.py` en `src/` y `tests/` debe tener exactamente **0 bytes** (vacío total: sin código, sin docstrings, sin comentarios, sin imports).
3. **Imports 100% Absolutos:**
   * Prohibidos los imports relativos (`from . import ...` o `from .. import ...`). Usa siempre la ruta canónica absoluta: `from src.domain...`, `from src.application...`.
4. **Tipado Estricto Exhaustivo:**
   * El 100% de las funciones y métodos en `src/domain/` y `src/application/` deben declarar Type Hints explícitos en todos sus parámetros y tipo de retorno.
5. **Controladores Delgados (*Thin Controllers*):**
   * Los routers en `src/infrastructure/fastapi/routers/` no contienen lógica de negocio ni manipulan ORMs directamente; delegan exclusivamente en `src/adapters/controllers/` o `src/application/use_cases/`.
6. **Configuración Centralizada y Cero Secretos Hardcodeados:**
   * Toda credencial, URL o parámetro dinámico debe provenir de `src/infrastructure/settings/config.py` (`Settings`). Prohibido quemar contraseñas, tokens JWT o connection strings en código.
7. **Exclusión Deliberada de `tests/` en el Análisis de Tipos:**
   * Los archivos en `tests/` están excluidos intencionalmente de Pyright por diseño de runtime. Prohibido añadir `# type: ignore`, `cast(Any, ...)` o `# noqa` en tests para silenciar advertencias de editor.

---

## 3. Matriz de Verificación (Constraint Gauntlet)
Antes de dar cualquier tarea por completada o sugerir un commit, verifica que el código supere el 100% de la siguiente batería:

```bash
# 1. Linter y Formato
ruff check .
ruff format --check .

# 2. Análisis Estático de Tipos (solo sobre src/)
pyright src/

# 3. Guantelete de Restricciones AST (Arquitectura, __init__.py de 0 bytes, imports, tipado, secretos)
python3 tests/test_architecture.py

# 4. Suite Completa de Tests
pytest --maxfail=1 --disable-warnings -v
```

## 4. Convención de Commits
* Utiliza el estándar **Conventional Commits**:
  * `feat: <descripcion>` (nuevas funcionalidades de negocio)
  * `fix: <descripcion>` (corrección de errores)
  * `refactor: <descripcion>` (cambios de código sin alterar comportamiento)
  * `test: <descripcion>` (añadir o corregir pruebas)
  * `docs: <descripcion>` (actualizaciones en documentación o specs)
  * `chore: <descripcion>` (mantenimiento, dependencias o configuración)
